9/// The SDL keyboard scancode representation.

12/// "physical" designation of a key.

14/// The values in this enumeration are based on the USB usage page standard:
15/// <https://www.usb.org/sites/default/files/documents/hut1_12v2.pdf>
16///

67/// `\`
68///
69/// Located at the lower left of the return key on ISO keyboards and at the
70/// right end of the QWERTY row on ANSI keyboards. Produces REVERSE SOLIDUS
71/// (backslash) and VERTICAL LINE in a US layout, REVERSE SOLIDUS and VERTICAL
72/// LINE in a UK Mac layout, NUMBER SIGN and TILDE in a UK Windows layout,
73/// DOLLAR SIGN and POUND SIGN in a Swiss German layout, NUMBER SIGN and
74/// APOSTROPHE in a German layout, GRAVE ACCENT and POUND SIGN in a French Mac
75/// layout, and ASTERISK and MICRO SIGN in a French Windows layout.
76pub const SDL_SCANCODE_BACKSLASH: SDL_Scancode = SDL_Scancode(49);
77/// Basically `\`, if you see it at all.
78///
79/// ISO USB keyboards actually use this code instead of 49 for the same key, but
80/// all OSes I've seen treat the two codes identically. So, as an implementor,
81/// unless your keyboard generates both of those codes and your OS treats them
82/// differently, you should generate SDL_SCANCODE_BACKSLASH instead of this
83/// code. As a user, you should not rely on this code because SDL will never
84/// generate it with most (all?) keyboards.
